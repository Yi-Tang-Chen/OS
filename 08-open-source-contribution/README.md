# 可重現缺陷與可審查的上游修改

## 學習從這裡開始

先讀 [逐步教學 LEARNING.md](LEARNING.md)：用途與例子 → 必要概念 → 第一個小實作 → 驗證與排錯。重要概念附 reference、閱讀範圍與學習重點。

先在固定 upstream commit 跑通原有測試，讀懂一個小案例，再練重現、修正與 regression test。

下方保留完整專案規格；初學時先按教學的小步驟前進，再回來對照驗收。

狀態：規劃中，已有規格與逐步教學，程式尚待實作。
環境：選定一個公開專案的local checkout；此階段先產出本地patch，不自動對外提交。
前置：至少一個前述project有可重現結果；熟悉git與測試。

## 要交付什麼

從真實issue或讀碼找出能重現的小缺陷，寫最小失敗測試、局部修正與清楚commit message。文件改進也可做，但履歷論述需和實際修改規模一致。

## 分層實作

- L1：固定upstream commit與CONTRIBUTING規範，建立問題重現與環境紀錄。
- L2：先失敗測試、再修正、再回歸；比較舊新版行為和影響範圍，準備patch。
- L3：模擬review迭代、rebase與CI失敗分析；對外PR或寄信由你檢查內容後決定。

## 效能與資源

重現命令、失敗測試數、影響範圍與review輪次；不以行數或PR數代替工程價值。

## 第一個動作

選用你已實際使用的library，找一個可本地重現的問題，先留下reproducer。

## 核心驗收

以下均為待驗收情境，並非已通過結果。

| ID | 觸發方式 | 必須驗證 | 結果／證據 |
| --- | --- | --- | --- |
| REPRO-01 | 同一測試跑upstream原版與修正版 | 原版失敗／修正版通過；不能靠改弱測試過關。 | 待實作 |
| SCOPE-01 | 檢查diff、格式、授權與相鄰測試 | 修改最小、沒有無關重構、符合專案規則。 | 待實作 |
| REVIEW-01 | 找另一人挑戰合約與邊界 | 記錄回應與修訂，不把review意見當成個人評價。 | 待實作 |
| STATUS-01 | 尚未送出、討論中、merged各階段 | 履歷和README如實標註，不虛構採用狀態。 | 待實作 |
